# extract-actions スキル

## このスキルの目的

会話ログ（`secretariat/memos/YYYY-MM-DD_会話ログ.md`）を読み込み、**社長の発言**から以下 3 種類のアクションを抽出して、各々の定位置に自動配置する:

- **todo**(行動タスク) → `secretariat/todos/YYYY-MM-DD.md`
- **decision**(意思決定・方針) → `ceo-office/decisions/YYYY-MM-DD_<topic>.md`
- **memo**(思考・モヤモヤ・構造化前の問い) → `secretariat/memos/YYYY-MM-DD_<topic>.md`

分類できない雑談・挨拶・体調報告・確認応答は **skip**(抽出しない)。確度 low は配置せずサマリーに列挙のみ。

---

## 呼び出し方と引数

- 自然言語: 「会話ログから抽出して」「ToDo/意思決定を拾って」「今日のログを整理して」
- スラッシュ: `/extract-actions`
- **引数(省略可)**: 対象会話ログの相対 or 絶対パス

**対象ファイルの決定**:
1. 引数が与えられた場合 → そのパスを使用
2. 引数なし → `secretariat/memos/$(TZ=Asia/Tokyo date +%F)_会話ログ.md`(JST 基準の本日)
3. ファイルが存在しない場合 → **明示的エラー**を返して終了。前日分などへのフォールバックは **しない**

---

## 処理フロー(厳守)

### Step 0. 作業ディレクトリの確認

プロジェクトルート(`secretariat/` や `ceo-office/` が直下にあるディレクトリ)で実行していることを確認する。`pwd` で確認し、異なる場合は社長に確認を求めて停止する。

### Step 1. 対象ログの特定

上記「呼び出し方」の規則で対象ファイルのパスを決定する。

### Step 2. 対象ログの読み込み

`Read` ツールで対象ログ全文を読む。

### Step 3. フロントマター解析(冪等性の第一関門)

ファイル先頭の YAML フロントマター(`---` で挟まれたブロック)を解析:

- `last_extracted_turn`(整数、無ければ `0`)
- `last_extracted_at`(ISO 8601 + JST オフセット、無ければ未設定)

フロントマター自体が無い場合は「未抽出ログ」と判定し、`last_extracted_turn = 0` とみなす。

### Step 4. ターン解析(社長発言のみ対象)

ログ本文から **社長サブセクション** を抽出する。anchor 正規表現:

```
^### \[#(\d+)(?: (\d{2}):(\d{2}) JST)?\] 社長\s*$
```

**重要な除外ルール**:
- **C-1**: `## 派生アクション` 行(およびそれ以降の全行)は抽出対象外。社長が手動で整理した既抽出リストなので二重取りになる
- **C-2**: `### [#NN ...] 秘書` サブセクションは **コンテキストとしてのみ参照**。秘書応答から todo/decision/memo を直接抽出しない(二重記録回避)
- `### [#NN] Cron発火` など「社長」以外のサブセクションも同様に対象外

各「社長」ブロックについて、そのブロックの本文(引用行 `>` で始まる社長の生発言 + 続く本文)を取得する。

### Step 5. 未抽出ターンの絞り込み(冪等性)

`ターン番号 > last_extracted_turn` のターンのみを分類対象に残す。既抽出ターンはスキップ。対象が 0 件なら Step 9 へ進み、「新規抽出なし」サマリーで終了(no-op)。

### Step 6. 分類(LLM による判定)

各「社長」ターンの発言内容を以下の 4 カテゴリで分類し、確度を付与する。

#### カテゴリ定義

| カテゴリ | 定義 |
|---|---|
| **todo** | これから実行する具体的な行動。タスク、作業、連絡、確認、購入等。いつ・何を・誰が の少なくとも「何を」が明確 |
| **decision** | 方針・採用・拒否・合意・方向性の確定。不可逆または準不可逆の判断 |
| **memo** | 未整理の思考、モヤモヤ、気になっていること、構造化前の問い。行動にも決定にも至っていない |
| **skip** | 挨拶、体調報告(情報共有のみ)、雑談、確認応答、既完了報告、秘書への単なる質問、数値・時刻の確認 |

#### 確度

| 確度 | 例 |
|---|---|
| **high** | 「〜する」「〜に決めた」「〜発送する」「明日までに〜」など断定・期限/担当明確 |
| **medium** | 「〜する予定」「〜したい」「〜で進めよう」など意図は明確だが断定ではない |
| **low** | 「〜かも」「〜かな?」「〜できたらいいな」「ちょっと気になる」など曖昧・仮定・願望 |

#### 判断迷い時のルール

- 「やる」系 → **todo**
- 「決めた／採用した／〜で行く／方針とする」系 → **decision**
- 「モヤモヤ／気になる／考えたい／迷っている」系 → **memo**
- 体調報告・雑談・確認応答・既完了報告 → **skip**

#### 単一発言が複数カテゴリに跨る場合

最も優先度の高い 1 カテゴリに寄せる(todo > decision > memo の優先)。**分割しない**。

#### few-shot 例

**todo(high)**
- 「カレンダーのMCP Serverの認証を今すぐ入れる」 → 明確な行動、即時実行
- 「応募者へ採用通知＋講習日メールを送る」 → 明確な行動＋相手明確

**decision(high)**
- 「A + 将来的にC」(permission mode の選定文脈) → 採用方針の決定
- 「面接地はファミレスに変える」 → 方針確定

**memo(medium)**
- 「集中力が続かなくてやりきれなかった部分があり、少しモヤモヤしています」 → 構造化前の思考
- 「『キリのいいところまで』で外出が 7 時間後ろ倒しになった。予定通り動きたい」 → パターン分析が必要な問い

**skip**
- 「胃もたれはだいぶ楽になっている」 → 体調報告・情報共有
- 「おはよう」「おつかれ」「了解」 → 挨拶・応答

**low(配置しない)**
- 「東銀座でお茶してもいいかも」 → 曖昧な願望、サマリーに列挙のみ
- 「そのうち〜してみたいな」 → 具体性なし

### Step 6.5. memo 第二段階分類(memo 判定された発言のみ)

Step 6 で **memo** に判定された発言について、以下 5 区分の細分類を付与する。memo 以外のカテゴリ(todo/decision/skip)には適用しない。

| 細分類 | 定義 | 例示キーワード |
|---|---|---|
| **モヤモヤ** | 不全感・引っかかり・言語化前の違和感 | 「モヤモヤ」「引っかかる」「スッキリしない」 |
| **アイデア** | 思いつき・試したい事・構想 | 「できるかな」「〜したいんだよね」「思ったんだけど」 |
| **悩み** | 選択肢の間で迷っている・決めかねている | 「迷っている」「どうしようか」「AとBで」 |
| **構造化前の問い** | 探索的・開かれた問い・方針決定前の思考 | 「なぜ〜」「本当に〜でいいのか」「〜って何だろう」 |
| **気になる事** | ちょっと気にかかっている事実・観察 | 「気になる」「そういえば」「ふと思ったんだけど」 |

**細分類の判定は 1 ターンにつき最も近い 1 区分のみ**(複数該当時はより上段を優先、分割しない)。境界が曖昧な場合は「構造化前の問い」を既定とする。

細分類結果は Step 7.3 の memo 出力テンプレ内「構造化 → 細分類」セクションに記録される。

### Step 7. 配置(high / medium のみ自動配置)

抽出結果のうち **high または medium** のものだけを以下のルールで配置する。**low はサマリーに列挙するのみ、ファイルは作らない**。

#### 7.1 todo の追記

ファイル: `secretariat/todos/YYYY-MM-DD.md`(YYYY-MM-DD は会話ログの日付)

**既存ファイルの扱い**:
- `## タスクリスト` セクションがある → その末尾に追記
- `## タスクリスト` が無い → ファイル末尾に `## タスクリスト(抽出)` を新設して追記
- ファイル自体が無い → 以下の最小テンプレで新規作成:

```markdown
# ToDo: YYYY-MM-DD

## タスクリスト(抽出)

## 関連

- 抽出元会話ログ: `memos/YYYY-MM-DD_会話ログ.md`
```

**追記する行フォーマット**:
```
- [ ] <タスク本文>(抽出元: #NN [HH:MM JST], 確度: high)
```

**重複排除**(同じ todo が既に書かれていないか):

1. 既存ファイル内の `- [ ]` 行をすべて収集
2. 各候補タスクを以下で正規化:
   - 前後空白をトリム
   - 連続空白 → 単一半角スペース
   - 全角英数 → 半角英数
   - 句読点(、。,.!?)を除去
   - `(抽出元: ...)`、`(担当: ...)` 等の丸括弧内注釈を除去
3. 比較:
   - 正規化後の **完全一致** → 重複とみなしスキップ
   - 正規化後の **双方向 substring 包含**(短い方が長い方に含まれる、かつ両者とも 8 文字以上) → 重複とみなしスキップ
4. 重複でなければ追記

> レーベンシュタイン距離や埋め込み類似度は使わない(誤検知リスクが費用対効果を上回る)。

#### 7.2 decision の新規作成

ファイル: `ceo-office/decisions/YYYY-MM-DD_<topic>.md`

**`<topic>` 生成ルール**:
- 1〜3 語、内容を要約する簡潔な名詞句
- 技術・固有名 → 英語 kebab-case(例: `permission-mode`, `org-design`)
- 日本語固有概念 → 日本語 OK(例: `面接地変更`, `モヤモヤ`)
- サニタイズ: `/ \ : * ? " < > |` は除去

**テンプレート**:

```markdown
---
決定日: YYYY-MM-DD
決定者: <CEO_HANDLE>
起案: extract-actions スキル(抽出)
適用範囲: <LLM が判断した適用範囲>
ステータス: 決定
抽出元: memos/YYYY-MM-DD_会話ログ.md #NN [HH:MM JST]
確度: <high|medium>
---

# 【決定】<topic 人間可読形>

## 1. 決定の要旨

<社長の発言を 1〜3 文で要約。引用符つきで生発言も併記>

> <社長の原文>

## 2. 背景・理由

<会話の前後文脈から読み取れる背景。秘書応答は context 参照のみ>

## 3. 関連

- 抽出元会話ログ: `memos/YYYY-MM-DD_会話ログ.md`(#NN [HH:MM JST])
```

**衝突回避**:
- 同名ファイルが既に存在する場合 → `YYYY-MM-DD_<topic>_v2.md`, `_v3.md`, ... と **サフィックスを付与**(上書き禁止)

#### 7.3 memo の新規作成

ファイル: `secretariat/memos/YYYY-MM-DD_<topic>.md`(会話ログ本体 `_会話ログ.md` とは別ファイル)

**テンプレート**:

```markdown
# メモ: <topic 人間可読形> (YYYY-MM-DD)

## 発端

<会話ログの文脈から、いつ・どんな流れで出た思考か 1〜3 文>

## 生の思考(社長の言葉のまま)

> <社長の原文を引用、改変しない>

## 構造化

### 細分類
<モヤモヤ / アイデア / 悩み / 構造化前の問い / 気になる事 から 1 つ、Step 6.5 の判定結果を記入>

### 要点

- <発言から読み取れる主要ポイント>

### 背景

- <パターン分析・過去の類似例との関連>

### 次のアクション案

- [ ] <もし具体化できるなら提案アクション>

## 関連

- 抽出元: `memos/YYYY-MM-DD_会話ログ.md` #NN [HH:MM JST]
- 抽出スキル: extract-actions
- 確度: <high|medium>
```

**衝突回避**: decision と同じ `_v2`, `_v3` サフィックス方式。

### Step 8. フロントマター更新(冪等性の確定)

対象会話ログの先頭フロントマターを更新する。

**C-3 ルール**:
- フロントマターが **存在しない場合**: ファイル **最先頭**(L1 のタイトル行より前)に以下を挿入:
  ```
  ---
  last_extracted_at: <ISO 8601 JST, e.g., 2026-04-22T15:30:00+09:00>
  last_extracted_turn: <今回処理した最大ターン番号>
  ---

  ```
  (フロントマター末尾 `---` の後に空行 1 行、その後は既存本文をそのまま保持)

- フロントマターが **既に存在する場合**: `last_extracted_at` と `last_extracted_turn` の値のみ **in-place 更新**。フロントマターを重複作成したり、他のフィールドを消去したりしない

- タイムスタンプ取得コマンド: `TZ=Asia/Tokyo date --iso-8601=seconds`

**重要**: フロントマター更新は Step 7(配置)がすべて成功した後にのみ行う。途中でエラーが起きた場合は更新せず、Step 10 でエラー報告する(次回再実行で同じターンを再処理できるようにする)。

### Step 9. 社長向けサマリー出力

以下フォーマットで報告:

```
会話ログ `memos/YYYY-MM-DD_会話ログ.md` から抽出しました。

- ToDo: X 件 → secretariat/todos/YYYY-MM-DD.md
  - <追記されたタスク1行サマリー>
  - ...
- 意思決定: Y 件
  - <作成ファイル名>: <要旨 1 行>
  - ...
- 思考メモ: Z 件
  - <作成ファイル名>: <要旨 1 行>
  - ...

未分類(確度 low): W 件 — 自動配置していません。必要なら昇格を指示してください:
  - [#NN HH:MM JST] <発言要旨>
  - ...

重複スキップ: V 件(既存 todo と一致したため追記を省略)

last_extracted_turn を #NN に更新しました。
```

抽出件数がすべて 0 の場合:

```
会話ログ `memos/YYYY-MM-DD_会話ログ.md` に新規抽出対象はありませんでした(既抽出ターン #NN まで完了)。
```

### Step 10. エラー処理

以下のケースで明示的エラーを返して停止する(部分成功状態でフロントマターを更新しない):

- 対象ファイルが存在しない(引数指定パス／本日ログ)
- 対象ファイルの読み込みに失敗
- 配置先ディレクトリが存在しない(`secretariat/todos/`, `ceo-office/decisions/`, `secretariat/memos/`)
  - この場合は mkdir で自動作成せず、社長に確認を求める(組織構造の変更に相当するため)
- Write/Edit が失敗した

エラー時の出力フォーマット:

```
❌ extract-actions 実行エラー:
- 原因: <具体的内容>
- 発生ステップ: <Step N>
- 影響: フロントマターは更新していません。原因解消後に再実行可能です。
```

## スコープ外(本スキルでは扱わない)

- watcher.sh との連携(自動起動)
- 日付変更検知による自動発火
- エクスポートスキルとの統合実行
- 複数日ログの一括処理(1 実行 = 1 日分のみ)

---

## 運用メモ

- **low の手動昇格**: サマリーの low 項目を社長が見て「その low を todo にして」と指示した場合、手動で該当ターンを todo として追記してよい(本スキルの範囲外だが、同一セッション内で応じられる)
- **トピック名の揺れ**: 同じ社長発言に対して異なる日に別の topic 名を生成してしまう可能性がある。それは許容(抽出元メタでトレース可能)
- **秘書応答のコンテキスト参照**: 社長発言の意図が判別しにくい場合、直後の秘書応答で補強してよい(例: 社長「A」→ 秘書「A案(全部スキップ)を採用」という文脈)。ただし抽出対象は社長発言のみ
- **`## 派生アクション` の尊重**: 社長が手動で整理したリストは本スキルで触らない(`# H2` 以降は未処理領域として放置)
