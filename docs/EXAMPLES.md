# EXAMPLES — 使用例

実際の運用フロー例を、シナリオ別に紹介します。

---

## Example 1: 朝のルーチン

### 社長の発話
```
社長: おはよう
```

### 期待される秘書の動き
1. 朝ルーチン3問を投げる
   - 今日の体調・気分は？
   - 気になっているタスクは？
   - 今日の優先トップ1つは？
2. 社長の回答を `secretariat/todos/YYYY-MM-DD.md` に記録
3. 優先トップは PM 部にも共有（依頼ファイル配置）

---

## Example 2: ToDo 入力

### 社長の発話
```
社長: 今日やること: A、B、C
```

### 秘書の動き
1. `todos/YYYY-MM-DD.md` を作成 or 追記
2. 各タスクをチェックボックス形式で記録
3. 担当部署を決定（5秒以内）
4. PM 部 / 各部署に依頼ファイル配置

---

## Example 3: 部署横断案件

### 社長の発話
```
社長: リサーチ部とマーケ部で、エステ業界の海外トレンドを調べてSNSネタを5案出して
```

### 秘書の動き
1. `secretariat/memos/YYYY-MM-DD_エステ海外トレンド.md` に案件記録
2. PM 部に調整依頼: `product-management/requests/YYYY-MM-DD_エステ海外トレンド.md`
3. PM が:
   - リサーチ部にチケット: `research/requests/YYYY-MM-DD_海外トレンド調査.md`
   - マーケ部にチケット: `marketing/requests/YYYY-MM-DD_SNSネタ生成.md`
4. リサーチ部が成果物 → マーケ部が SNS ネタに変換 → PM が統合 → 秘書 → 社長

### 自動化の流れ
- 各部署が成果物を `<dept>/reports/` に配置
- watcher が検知 → 秘書 inbox に通知
- 秘書が統合して社長に報告

## Example 4: 思考の吐き出し

### 社長の発話
```
社長: 〇〇について最近モヤモヤしてるんだけど...
```

### 秘書の動き
1. **遮らずまず受け止める**
2. `secretariat/memos/YYYY-MM-DD_〇〇について.md` に生の思考を記録
3. 社長が話し終わってから（明示的に求められたら）構造化提案
4. アクション可能な項目があれば `todos/` に転記

### NG パターン
- 即座に「では◯◯しましょう」と解決提案
- 評価・批判（「それは違うのでは？」）
- 整理しすぎて感情を切り離す

## Example 5: 意思決定の記録

### 社長の発話
```
社長: 〇〇に決めた。値段は△△で、開業は◇月にする。
```

### 秘書の動き
1. `ceo-office/decisions/YYYY-MM-DD_〇〇決定.md` に **不可逆記録**
2. 関連部署へ通知（経理: 価格反映 / マーケ: 訴求調整 / etc.）
3. 進行中プロジェクトの README.md にも反映指示

### decisions の書式
```markdown
# 意思決定: 〇〇

## 日付
YYYY-MM-DD

## 背景
（どういう状況で検討が始まったか）

## 選択肢
- A: ...
- B: ...
- C: ...

## 評価
| 軸 | A | B | C |
...

## 決定
（選んだ選択肢と理由）

## 次のアクション
- [ ] ...
```

## Example 6: 緊急エスカレーション

### 法務部からの緊急報告
```
法務部: 景表法違反のリスクが高い広告コピーを発見、即時修正必要
```

### フロー
1. 法務部が `legal/reports/YYYY-MM-DD_緊急_景表法リスク.md` 配置
2. watcher 検知 → 秘書 inbox に通知
3. 秘書がファイル名に `緊急` を検知 → 即座に社長へ通知
4. 社長判断 → マーケ部にコピー修正指示

### 緊急度の見極め
- ファイル名に `緊急_` `🚨_` 等のプレフィックスを付けるルール
- 秘書 AI は inbox 確認時にこれを優先処理

## Example 7: 再帰的戦略立案ループ

### 社長の発話
```
社長: この案件について、周辺状況や社会情勢など様々な要素を加味して、
どのようなコンセプトや経営戦略で望むのがいいのか検討したい。
サブエージェント多重起動で、終わらないように続けて欲しい。
```

### 動き
1. 秘書（または経営企画）がオーケストレーターになる
2. ラウンド1: 並列5サブエージェントで多角検討
   - エビデンス収集
   - 競合調査
   - 顧客分析
   - 戦略フレーム適用
   - 否定的レビュー
3. 各 agent の結果を `corporate-planning/plans/<案件>/round-01/agent-N_*.md` に保存
4. ラウンド統合: `synthesis.md` で集約
5. ラウンド2を起動（前ラウンドの成果を引き継ぎ）
6. ラウンド3、4...と続行

### 実例
本テンプレートでは、ある実プロジェクトで Round 1〜8、合計 40,000行超の分析データベースを生成した実績があります。
クライアントインタビュー前段階の戦略立案を、社長の睡眠中に AI が完遂しました。

## Example 8: Slack 連携運用

### 設定後の使い方

#### 社長の発話
```
社長: Slackの#メインに、進捗サマリーを投稿して
```

### 秘書の動き
1. 直近の `secretariat/memos/`, `<dept>/reports/` を確認
2. サマリー作成
3. Slack MCP 経由で `chat.postMessage` 実行
4. 投稿完了を社長に報告

### Canvas 更新
進捗が大きい時:
1. `conversations.canvases.create` または `canvases.edit` で Dashboard Canvas 更新
2. メンバーが Pin 留めから即見られる

## Example 9: クライアント案件管理

### consulting / coaching 業者の使い方
1. クライアント別に `corporate-planning/plans/<client-name>/` ディレクトリ
2. `client.md` にクライアント情報（機密、.gitignore 推奨）
3. `scope.md` にスコープ・契約
4. `deliverables/` に成果物ファイル
5. `hearing/` にヒアリング記録
6. `retrospective.md` にプロジェクト終了時の振り返り

### Slack で進捗共有
- クライアント招待した Slack channel に AI が自動投稿
- 「直接接触禁止」のルールを CLAUDE.md で明示
- 質問は「全て社長経由」

## Tips

### 1. 朝のルーチンを毎日回す
社長が「おはよう」と言うだけで会社が動き出す。
タスク化されないと忘れてしまう案件を、毎朝吐き出す習慣化。

### 2. 思考メモを温存
モヤモヤを `memos/` に書き溜める。3-6ヶ月後に振り返ると判断の傾向が見える。

### 3. lessons.md を聖典に
社長の指摘を即座に lessons.md へ。
1年積み重ねれば、社長 AI 全体の質が劇的に上がる。

### 4. 部署の名前を変えない
独自の部署名（例: 「魔法部」「冒険部」）を付けたくなるが、汎用部署名のままが他人に伝わる。
